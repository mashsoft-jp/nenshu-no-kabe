## 初期移行の管理方法

ソース・テスト・仕様を個別ファイルで登録する。生成物 `index.html` は `python3 build.py` で再現し、重複するソースとしてはコミットしない。生成後の内容は元のv0.7と照合する。この管理上の変更でアプリの画面や計算は変更しない。

初期コミット前のmainはREADMEのみだった。初期PR #1はD13でマージ済み。

## Pages公開の構成

D14に対する実装は `.github/workflows/pages.yml`。main向けPRでテスト・ビルド・公開ファイルの検査を行い、mainへのpushまたはmainの手動実行時だけ公開する。生成HTML1ファイルのみを一時ディレクトリからアップロードする。開発資料・テスト・Git履歴・利用者設定は配信対象外。HTML内のクライアントコードは閲覧できる。

実際の公開にはGitHub側のPages有効化と対応プランが必要。リポジトリの公開化、契約アップグレード、予算の変更は承認に含めず、必要ならユーザーへ確認する。CI・Bugbotの確認前の自動マージは設定しない。通常のPagesサイトは非公開プレビューとは異なる。

Pages対応はホスティング設定であり、CALC-001 / QA-001等の税制・計算の独立検証を完了させたものではない。既存資料の「公開先未決定」「初期PR未マージ」は初期登録時点の記録で、現在の状態はD13・D14と `docs/PAGES.md` を優先する。

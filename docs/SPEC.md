# 仕様書ドラフト

対象：年収の壁 v0.7 / 整理日：2026-09-09

この文書は現行ソースと会話の要件を整理したもの。数値上限などの試作制限は、ユーザー確定要件とは区別する。制度の数字を新しく承認する文書ではない。

## 1. 画面構成

単一ページを維持する。PCは入力と結果を左右に置き、狭幅では縦に並べる。

1. ヘッダー：年収の壁、入力値の非送信表示、結果コピー。
2. 給与条件：月給、任意賞与、算出年収、支部・年齢。詳細条件は折りたたむ。
3. 手取り額：通常月、年間（賞与込み）、年額÷12の月平均、額面年収の式。
4. 内訳：月額と年額の構成バー・同一表。項目別「詳細」。
5. 所得税の変更：初期状態は閉じたオプション。
6. 年収別グラフ、計算条件の補足、比較表・CSV、制度の前提・資料。

税制比較を前面に出して手取りを押し下げない。見出しは「給与条件」「手取り額」「内訳」「所得税の変更」等にする。

## 2. 入力と年収

### 基本入力

| 値 | 現行仕様 |
| --- | --- |
| 月給 | 額面・手当込み、円単位。毎月同額を想定 |
| 賞与 | 任意。支給月1〜12月・額面を追加/削除。最大3件は試作制限 |
| 額面年収 | `monthlyGross * 12 + bonusesのgross合計`。直接編集せず導出 |
| 支部 | 居住地ではなく協会けんぽ加入支部。47支部の実装データを使用 |
| 年齢 | 20〜64歳。資格判定や誕生日月の再現はしない |

エンジンの月給範囲は80,000〜8,333,333円、年収上限は100,000,000円。賞与を含む計算年収でも上限を確認する。最低年収等の制限は給与モデルの入力範囲であり、社会保険加入条件を判定した結果ではない。

### 詳細条件

非課税通勤手当、雇用保険区分、決定済みの標準報酬月額、前年の給与収入・社会保険料、通知済み住民税、年間社会保険料の直接指定、その他給与控除を保持する。賞与が1〜3月にある場合は、健康保険の上限判定用に前年4〜12月の標準賞与累計を指定する。前年賞与額を当年の額面年収へ加算しない。

非課税通勤手当は入力した額面に含まれる内数。その他給与控除は税法上の所得控除と区別する。

### 扶養条件

配偶者以外の国内居住の税法上の扶養親族を、16歳未満・16〜18歳・19〜22歳・23〜69歳・70歳以上（同居老親等以外）・同居老親等で入力する。初期値0人、各所得年の年末時点の区分。通常月の源泉徴収人数と2025年の住民税用扶養は、今年と同じと仮定する方法・個別指定を選べる。

2026年分所得税と2027年度住民税には今年の扶養控除、2026年度住民税概算には前年の扶養控除を使う。23歳未満の扶養親族による所得金額調整控除、住民税の調整控除・非課税人数も反映。通知書の直接年額・月額は変更しない。各項目の「詳細」に根拠を表示する。

JSON version 6で保存し、旧version 1〜3は扶養0人として移行・通知して従来結果を維持する。CSV・コピーにも扶養条件を含める。配偶者・その他控除は次節、扶養の控除額・対象年・検証は `docs/DEPENDENTS.md` を参照。

### 配偶者・その他の控除（2026-09-10追加）

配偶者（特別）・障害者・ひとり親／寡婦・勤労学生・特定親族特別控除を、資格条件と所得に応じて計算する。iDeCo等、追加社会保険、生命・地震保険、医療費、雑損、寄附金は算定済み控除額を入力。住宅ローン等の税額控除は、所得控除と別欄に入力し税額を上限に適用する。支払額からの控除額算定・住宅ローン等の制度上限の自動判定は含めない。

今年の条件は2026年所得税・2027年度住民税概算、前年の条件は2026年度住民税概算に使用。今年と前年の同一仮定・個別指定を選択する。通常月の源泉人数は配偶者・本人条件も含めるが、勤務先への申告人数を手入力した場合は優先。保険等の年額控除は通常月に流用しない。通知書住民税は保持。金額・資格・詳細な対象外は `docs/DEDUCTIONS.md` を参照。

設定JSONはversion 6で、旧version 1〜4には追加控除なしを補い通知。旧version 4の扶養条件を保持。CSV・コピー・各税の詳細に条件と金額を追加する。

## 3. 表示する金額

| 結果 | 意味 |
| --- | --- |
| 通常月の手取り | 月給 − 通常月の社会保険料 − 源泉所得税等 − 給与天引き住民税等 − その他月額控除 |
| 年間の手取り | 月給×12＋賞与 − 年間社会保険料 − 年間所得税等 − モデル上の年間住民税等 − その他月額控除×12 |
| 年間の月平均 | 年間手取り÷12。通常月の振込額と同じとは限らない |
| 仮想制度の差額 | 同じ給与・保険条件で計算した変更後年額 − 現行制度年額 |

自動概算では通常月と年間で対象期間・所得税の計算方法・住民税年度が異なる。通知書の年額を入力した場合は、その通知書の対象年度の年額と月額を使用する。年額を実際の1〜12月の入出金合計と呼ばない。現行モデルの期間は `PROJECT.md` と `SOURCES.md` に記載する。

### 3.1 通知書の住民税年額と月額

「通知書の年額を入力」を選択・編集すると、通常月を「通知書の年額から算出」に切り替える。ただし、通知書の月額を直接指定している場合はその値を優先し、上書きしない。月額の概算を明示的に選び直す方法も残す。

給与特別徴収の年額（森林環境税込み）だけを対象とする。通常の12回徴収では、7月〜翌5月の各月額を `floor(年額 / 1200) * 100`、6月分を `年額 − 各月額 * 11` とする。通知書に6月全額徴収の指定がある場合は「6月に全額徴収」を選ぶ。少額の判定を協会けんぽ支部から推測しない。

年額240,500円の場合、6月20,500円、7月〜翌5月各20,000円。通常月の手取りには後者を使い、住民税差だけを反映した6月の手取りも併記する。6月の他の控除は通常月と同じ固定条件であり、実際の6月の給与計算を再現するものではない。

通知書の年額・配分・計算式は住民税の「詳細」と入力欄に表示する。通知書年額はその対象年度の固定額として扱い、2027年度の予測額と表示しない。翌年度の自動概算へ戻すと、年額連動中の通常月は2026年度の概算へ戻す。通知書月額の直接指定中はその値を保持する。

年度途中の転職・徴収開始・税額変更、普通徴収や年金からの特別徴収、複数徴収方法の合算、通知書の未徴収残額の再配分は対象外。配分が通知書と異なる場合は通知書の月額を優先する。

設定JSONはversion 6（配偶者・追加控除）。`monthlyResidentMode: annual` と `residentCollectionMode: split|june` を保存する。旧version 2は年額・月額の独立計算を維持して移行し、年額入力がある場合はその旨を通知する。旧version 1の給与変換も維持する。CSV・コピーには月額の根拠、通知書配分、年額の根拠を含める。住民税連動の詳細は `docs/RESIDENT-NOTICE.md`。扶養条件追加後の保存形式は `docs/DEPENDENTS.md`。

## 4. 内訳と詳細

健康保険、介護保険、厚生年金、子ども・子育て支援金、雇用保険、所得税等、住民税等、その他控除、手取り等を表示する。年額社会保険料を手入力した場合は自動計算した細目の合計と混同しない。

「詳細」は項目名と対応付け、押した項目の直下に計算式と条件を表示する。同時に複数項目を開ける。条件変更後も展開状態を保ち、内容だけを再計算する。`aria-expanded`、対象要素との対応、フォーカス表示を保つ。

健康保険の表示形式例：

```text
標準報酬月額 × 支部の保険料率 ÷ 2（支部名）
月額 × 12 ＋ 賞与分 ＝ 年額
```

式に使う値はその時の計算結果から作る。標準報酬月額、本人負担、端数処理、対象外理由を表示する。所得税は同じ項目の詳細内で月次の計算条件と年間の課税所得の導出・税率区間別内訳を示す。独立した重複「計算根拠」カードは再導入しない。

## 5. 所得税の仮想変更

設定欄の見出しは「税率設定」とし、括弧付きの「仮想制度」等は付けない。設定欄の先頭に、全段階の税率をまとめた階段状の折れ線グラフを置く。横軸は課税所得（万円）を金額に比例して表示し、縦軸は所得税率（%）。各区間は水平、境界では垂直に変化し、途中を斜線で補間しない。最終段階は上限なしとして矢印と説明で示す。

表示範囲は全境界を含めて自動調整し、下段の年収別グラフの表示上限には連動しない。金額・税率の直接入力、スライダー、区分の分割・削除、変更例、戻す・現行に戻す、JSON読込、既存のグラフの境界ドラッグに追随する。不正な区分入力中は古いグラフを残さず、エラー案内に置き換える。

グラフのタップまたは左右キーで段階を選び、同じ入力欄・スライダーで編集する。選択だけでは給与や税率を変更しない。選択中の区間と税率はグラフ直下に表示する。狭幅・密集区分では重なるラベルを省き、正確な値は選択表示と既存の数値欄で確認できる。詳細な変更・検証記録は `docs/UI-RATE-CHART.md`。

現行制度は編集不可。仮想側の課税所得上限・税率を編集し、区分の分割・削除に対応する。現行の実装制限は1〜20段階、率0〜100%、最終区間は上限なし。上限の非昇順、無効な数字等を拒否する。率は下位より低い設定も仮想制度として許容し、単調増加を勝手に要件化しない。

速算表の控除額を固定して流用せず、課税所得を区間ごとに分けて算出する。基礎控除変更は現行実装にある追加機能として維持する。給与所得控除・住民税制度・社会保険加入条件まで同時に変えない。

変更後の年間手取り・差額と内訳の変更後列を表示する。通常月の源泉徴収は変更しない。折りたたみを閉じても設定を保持し、変更中を示す。「現行に戻す」で取り消す。

## 6. 賞与と社会保険

月給と賞与を分けて計算し、賞与を月給へ均して標準報酬月額を決めない。同月賞与の集計、標準賞与額の端数処理、健康保険の年度枠と厚生年金の月枠、前年枠を現行のモデルとして扱う。

賞与ごとの源泉徴収税額や支給時の振込額は算出しない。賞与を年間給与所得へ合算して年間所得税を計算する。実際の支給月ごとの料率・資格・免除等を再現する機能は未実装。

## 7. グラフ・保存

グラフは年収×手取り、年収×増減額、税率の段階を切り替える。年収を動かす場合は賞与を固定し、月給を変える。円単位への変換・丸めで目標年収と差が出る場合、実際に計算した年収と入力を整合させる。

設定JSONは月給・賞与・制度設定等を保存する。旧形式は既存の移行処理を維持し、変換時には通知する。独自JSON形式を新設する場合はマイグレーションを設ける。CSVには月給・賞与・計算に使った年収と結果を含める。不正形式・上限超過等はエラーとして扱う。

## 8. 非機能と未決事項

現在は外部送信・自動保存・アクセス解析なしのブラウザ内計算。公式資料のリンク操作のみ外部通信を伴う。サーバー・認証・DB・フレームワーク移行・クラウド保存は未決定。

Chrome相当の既存テストはあるが、Safari/Firefox/実機モバイルの網羅的な検証は未完了。一般公開、利用案内、ライセンス、制度データの更新運用は別の完了条件を設ける。

## 9. 仕様の根拠

ユーザー確定事項は会話履歴と `docs/DECISIONS.md`。実装の確認先は `unified-engine.js`、`unified-ui.js`、`unified-view.html`、既存エンジン・テスト。制度の一次資料リンクは `SOURCES.md` に引き継いでいるが、公開前に適用時期・数値・丸めと照合する。

## 2026-09-10 子ども・子育て支援金の端数処理

利用者の依頼により、当面、支援金の本人負担額は標準報酬月額・標準賞与額 × 0.23% ÷ 2 を単独計算し、1円未満を切り上げる。月給分は月額を切り上げてから12倍し、賞与分は既存の同月合算・年度上限適用後に切り上げる。健康保険等の端数処理は維持する。法定の一律切上げへの制度改定ではなく、給与明細に合わせる計算上の設定として詳細に明記する。

## 2026-09-10 月給から住民税を天引きしない選択

「通常月の住民税」に「月給から天引きしない（自分で別途支払う）」を追加。通常月の住民税は0円、年間の税額・年間手取りは従来どおり別払いの負担を含める。年額・年額計算方法を変更しても天引きなしを維持する。別払い時は年額入力の説明を切り替え、給与特別徴収の配分と6月手取りは非表示、CSVの配分欄は空欄とする。普通徴収の各期納付額は計算しない。

JSON version 6に `monthlyResidentMode: none` を追加。旧version 1〜5は既存の移行を維持し、天引き方法を勝手に変えない。旧versionでのnone指定と未知のモードは拒否する。既定は従来どおり前年同額の概算。受入条件は月額のみ0円・年額維持、年額編集後の選択維持、JSON復元、狭幅での表示。

## 2026-09-10 初期設定のステップ入力

初期表示を「給与・賞与」「社会保険」「扶養・控除」「住民税」「入力内容の確認」の5ステップにする。設定中は結果・グラフ・所得税変更を隠し、「手取りを表示」で既存の同一ページの通常月・年間表示に進む。計算・入力の初期値は変更しない。

戻る操作は入力値を保持する。扶養・追加控除は必要な項目だけ展開。「一覧で入力する」で従来の編集画面へ切り替え、給与条件の「ステップ式で入力」で再開できる。既存の入力要素を移動して利用し、状態を複製しない。保存・読込は既存JSON version 6を維持。進行状況の自動保存や送信は追加しない。

各ステップの「次へ」で現在の欄の形式・範囲を検証し、不正な入力があればその場で案内する。他のステップの未入力・不正値で移動を止めず、最終表示前に全体の計算条件を検証する。戻る・一覧への切り替えは修正のために常時利用できる。ステップ移動後は見出しへフォーカスし、入力欄のEnterでも次へ進める。最終確認で主要条件と既定値利用の注意を表示する。

受入条件：初期状態では給与入力のみ表示、前後移動で値保持、住民税別払い・扶養入力、最終結果の一致、一覧との往復、設定復元、エラー停止、320〜1440pxで横はみ出しなし。制度変更とは別のUI変更として実装。

## 2026-09-10 報酬の区分と雇用保険

最初の入力に「従業員の給与」「代表取締役・役員報酬のみ」「兼務役員・その他（個別指定）」を追加。従業員は一般事業0.5%を既定とし、既に0.6%を選んでいれば保持する。役員報酬のみへ切り替えると月給・賞与とも雇用保険0、保険料率欄は編集不可。他の社会保険や税率は変更しない。従業員から非加入を直接選んだ場合は個別指定に切り替える。

代表取締役・業務執行権のある取締役は被保険者とならず、その他役員も原則対象外。雇用関係が認められる兼務役員は例外があるため個別指定を残す。ただし役員報酬と雇用保険対象の給与が混在する計算は未対応と明示し、一律に全役員を非加入と断定しない。一次資料確認：北海道ハローワーク「雇用保険の被保険者の種類と要件」 https://jsite.mhlw.go.jp/hokkaido-hellowork/list/sapporo/jigyosyomainhokennryoumada/hoken3/01.html （2026-09-10閲覧）。保険料率改定ではなく入力連動の追加。

JSON version 7にpayType（employee/officer/custom）を保存。旧version 1〜6は雇用保険率を変更せず、0ならcustom、それ以外ならemployeeとして移行する。旧ファイルから役員と推測しない。version 7の区分欠落・未知値、officerと非ゼロ保険料率の矛盾は拒否する。確認画面・CSV・コピーにも報酬区分を含める。給与設定の自動送信・自動保存は追加しない。
